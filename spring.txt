[HTTP]
    - 프로토콜: 컴퓨터 내부 또는 사이에서, 데이터의 교환 방식을 정의하는 규칙 체계
                기기 간 동신은 교환되는 데이터의 형식에 대해 상호 협의를 요구함

    - 기본 요소
        1) 구문 : 전송하려는 데이터의 형식 등을 규정
        2) 의미 : 두 기기 간의 효율적인/정확한 정보 전송을 위한 협조 사항, 오류 관리를 위한 제어 정보 규정
        3) 시간 : 두 기기 간의 통신 속도와 메시지 순서 제어 등을 규정


    - HTTP : 인터넷상에서 데이터를 주고받기 위한 서버/클라이언트 모델을 따르는 프로토콜
    - IP : 네트워크에서 장치를 구분하는 고유 주소
    - PORT : 프로그램 번호

    - URI : 자원을 식별하는 전체 개념
    - URL : 자원의 위치를 나타내는 URI의 한 종류

    - 클라이언트 : 서비스를 요청하는 쪽 -> (Request)
    - 서버 : 요청을 처리하는 쪽 -> (Response)
    
    
    ★ HTTP 프로토콜은 상태가 없는 프로토콜이다.
       데이터 전달 중에는 상태를 가지고 있다가 전달이 끝나면 다시 가지고 있지 않은 상태가 된다.
       각각의 데이터 요청이 서로 독립적으로 관리된다.(서로 연관이 없음) -> 다수의 요청 처리 및 서버의 부하를 줄일 수 있는 성능 상 이점이 존재한다.
       일반적으로 TCP/IP 통신 위에서 동작
       기본 포트는 80번이다.

    ★ HTTP 메서드
        get: 서버의 리소스를 조회
        post: 서버에 새로운 데이터를 등록하거나 생성
        put: 리소스를 완전히 대체함, 데이터가 없으면 새로 만듬
        patch: 리소스의 일부만 수정
        delete: 서버의 리소스를 삭제할 때 사용

[WAS]
    - 정적(Static)
        파일 경로 이름을 받아 경로와 일치하는 file contents를 반환함
        항상 동일한 페이지를 반환

    - 동적(Dynamic)
        인자의 내용에 맞게 동적인 콘텐츠를 반환함. -> 웹 서버에 의해 실행되는 프로그램을 통해 만들어진 결과물
        * Servlet(서블렛) was 위에서 돌아가는 자바 프로그램 -> 서블렛 안에 doGet() 구현하기

    ★ Servlet(서블렛)
        *클라이언트의 요청 처리와 결과 반환을 담은 Servlet 클래스*의 구현 규칙을 지킨 자바 웹프로그래밍 기술
        MVC 패턴에서 Controller의 역할을 담당.
        서블릿 하나 == 하나의 클래스이므로 HttpServlet 클래스를 상속 받아 구현해야 함.
                        * HttpServlet엔 웹 상에서 클라이언트 요청이 있을 때 해당 서블릿을 실행하는 모든 조건이 포함된다.
        tomcat에서 제공(spring에 내장됨)
        @SpringBootApplication -> 서블렛 불러오는 어노테이션
        (PORT 번호 8080)

    - 서블렛 컨테이너
        컨테이너: 웹 컴포넌트를 저장하는 저장소 역할, 메모리 로딩, 객체 생성 및 초기화 등 서블릿의 생명주기를 관리하고 JSP를 서블릿으로 변환하는 기능을 수행하는 프로그램
        
        서블렛 컨테이너는 서블렛 컴포넌트를 실행하는 환경 제공함.
        클라이언트의 HTTP 요청을 서블릿에 전달 후 서블릿의 HTTP 응답 결과를 클라이언트에게 돌려줌
        
    ★ Web Server
        개념: 웹 브라우저 클라이언트로부터 요청을 받아 정적 컨텐츠를 제공하는 컴퓨터 프로그램

        기능: HTTP 프로토콜을 기반으로 클라이언트의 요청을 서비스하는 기능을 담당
              정적 컨텐츠 제공 시, WAS를 거치지 않고 바로 자원 제공
              동적 컨텐츠 제공 시 요청을 WAS에 전달한다. 이후 WAS가 처리한 결과를 클라이언트에게 전달한다. (Response)

    ★ WAS (웹 애플리케이션 서버)
        개념 : DB 조회 등의 다양한 로직 처리를 요구하는 동적인 컨텐츠를 제공하기 위해 만들어진 애플리케이션 서버
               '웹 컨테이너' 혹은 '서블릿 컨테이너'라고도 불림
               container -> JSP와 servlet을 실행시킬 수 있는 소프트웨어
               * 즉 WAS는 JSP와 servlet 구동 환경을 제공

    - WAS 동작구조
    1) Web Server는 웹 브라우저(클라이언트)로부터 HTTP 요청을 받음
    2) 정적이면 응답 / *동적이면 클라이언트의 요청을 WAS에 보낸다.*
    3) WAS가 관련된 Servlet을 메모리에 올린다.
    4) WAS는 web.xml을 참조하여 Web Container(Servlet Container)에서 해당 Servlet에 대한 스레드를 할당한다(스레드풀 이용하여 미리 만들어진 스레드들을 할당)
    5) HttpServletRequest와 HttpServletResponse 객체를 생성하여 Servlet에 전달한다.
        5-1. Thread는 Servlet의 service 메서드 호출
        5-2. service() 메서드는 요청에 맞게 doGet() 또는 doPost() 등의 HTTP 메서드를 호출
    6) doGet() / doPost() 메서드는 인자에 맞게 생성된 동적 페이지를 Response 객체에 담아 WAS에 전달함
    7) WAS는 Response 객체를 HttpResponse 형태로 바꾸어 Web Server에 전달한다.
    8) 생성된 Thread를 종료하고, HttpServletRequest와 HttpServletResponse 객체를 제거한다( destroy() )


[어노테이션]
    @SpringBootApplication : Spring 실행할 때 spring에 필요한 기본 세팅 지원
                                (1. 내장톰캣지원, 2.서블릿자동등록)

    @RestController : Spring에선 서블릿을 상속이 아니라 @Controller 어노테이션으로 지원 + RestController (HTTP content type 자동으로 application/json으로 세팅)

    @GetMapping( "/board/findAll" ) : 만약, HTTP 요청이 GET이면 해당 메소드로 연결한다. + URL 만들기(중복없이) -> findAll()
    @PostMapping( "/board/save" ) : 만약, HTTP 요청이 POST이면 해당 메소드로 연결한다. + URL 만들기(중복없이) -> save()
    @PutMapping( "/board/update" ) : 만약, HTTP 요청이 PUT이면 해당 메소드로 연결한다. + URL 만들기(중복없이) -> update()
    @DeleteMapping( "/board/delete" ) : 만약, HTTP 요청이 DELETE이면 해당 메소드로 연결한다. + URL 만들기(중복없이) -> delete()
