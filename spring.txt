[HTTP]
    - 프로토콜: 컴퓨터 내부 또는 사이에서, 데이터의 교환 방식을 정의하는 규칙 체계
                기기 간 동신은 교환되는 데이터의 형식에 대해 상호 협의를 요구함

    - 기본 요소
        1) 구문 : 전송하려는 데이터의 형식 등을 규정
        2) 의미 : 두 기기 간의 효율적인/정확한 정보 전송을 위한 협조 사항, 오류 관리를 위한 제어 정보 규정
        3) 시간 : 두 기기 간의 통신 속도와 메시지 순서 제어 등을 규정


    - HTTP : 인터넷상에서 데이터를 주고받기 위한 서버/클라이언트 모델을 따르는 프로토콜
    - IP : 네트워크에서 장치를 구분하는 고유 주소
    - PORT : 프로그램 번호

    - URI : 자원을 식별하는 전체 개념
    - URL : 자원의 위치를 나타내는 URI의 한 종류

    - 클라이언트 : 서비스를 요청하는 쪽 -> (Request)
    - 서버 : 요청을 처리하는 쪽 -> (Response)
    
    
    ★ HTTP 프로토콜은 상태가 없는 프로토콜이다.
       데이터 전달 중에는 상태를 가지고 있다가 전달이 끝나면 다시 가지고 있지 않은 상태가 된다.
       각각의 데이터 요청이 서로 독립적으로 관리된다.(서로 연관이 없음) -> 다수의 요청 처리 및 서버의 부하를 줄일 수 있는 성능 상 이점이 존재한다.
       일반적으로 TCP/IP 통신 위에서 동작
       기본 포트는 80번이다.

    ★ HTTP 메서드
        get: 서버의 리소스를 조회
        post: 서버에 새로운 데이터를 등록하거나 생성
        put: 리소스를 완전히 대체함, 데이터가 없으면 새로 만듬
        patch: 리소스의 일부만 수정
        delete: 서버의 리소스를 삭제할 때 사용

[WAS]
    - 정적(Static)
        파일 경로 이름을 받아 경로와 일치하는 file contents를 반환함
        항상 동일한 페이지를 반환

    - 동적(Dynamic)
        인자의 내용에 맞게 동적인 콘텐츠를 반환함. -> 웹 서버에 의해 실행되는 프로그램을 통해 만들어진 결과물
        * Servlet(서블렛) was 위에서 돌아가는 자바 프로그램 -> 서블렛 안에 doGet() 구현하기

    ★ Servlet(서블렛)
        *클라이언트의 요청 처리와 결과 반환을 담은 Servlet 클래스*의 구현 규칙을 지킨 자바 웹프로그래밍 기술
        MVC 패턴에서 Controller의 역할을 담당.
        서블릿 하나 == 하나의 클래스이므로 HttpServlet 클래스를 상속 받아 구현해야 함.
                        * HttpServlet엔 웹 상에서 클라이언트 요청이 있을 때 해당 서블릿을 실행하는 모든 조건이 포함된다.
        tomcat에서 제공(spring에 내장됨)
        @SpringBootApplication -> 서블렛 불러오는 어노테이션
        (PORT 번호 8080)

    - 서블렛 컨테이너
        컨테이너: 웹 컴포넌트를 저장하는 저장소 역할, 메모리 로딩, 객체 생성 및 초기화 등 서블릿의 생명주기를 관리하고 JSP를 서블릿으로 변환하는 기능을 수행하는 프로그램
        
        서블렛 컨테이너는 서블렛 컴포넌트를 실행하는 환경 제공함.
        클라이언트의 HTTP 요청을 서블릿에 전달 후 서블릿의 HTTP 응답 결과를 클라이언트에게 돌려줌
        
    ★ Web Server
        개념: 웹 브라우저 클라이언트로부터 요청을 받아 정적 컨텐츠를 제공하는 컴퓨터 프로그램

        기능: HTTP 프로토콜을 기반으로 클라이언트의 요청을 서비스하는 기능을 담당
              정적 컨텐츠 제공 시, WAS를 거치지 않고 바로 자원 제공
              동적 컨텐츠 제공 시 요청을 WAS에 전달한다. 이후 WAS가 처리한 결과를 클라이언트에게 전달한다. (Response)

    ★ WAS (웹 애플리케이션 서버)
        개념 : DB 조회 등의 다양한 로직 처리를 요구하는 동적인 컨텐츠를 제공하기 위해 만들어진 애플리케이션 서버
               '웹 컨테이너' 혹은 '서블릿 컨테이너'라고도 불림
               container -> JSP와 servlet을 실행시킬 수 있는 소프트웨어
               * 즉 WAS는 JSP와 servlet 구동 환경을 제공

    - WAS 동작구조
    1) Web Server는 웹 브라우저(클라이언트)로부터 HTTP 요청을 받음
    2) 정적이면 응답 / *동적이면 클라이언트의 요청을 WAS에 보낸다.*
    3) WAS가 관련된 Servlet을 메모리에 올린다.
    4) WAS는 web.xml을 참조하여 Web Container(Servlet Container)에서 해당 Servlet에 대한 스레드를 할당한다(스레드풀 이용하여 미리 만들어진 스레드들을 할당)
    5) HttpServletRequest와 HttpServletResponse 객체를 생성하여 Servlet에 전달한다.
        5-1. Thread는 Servlet의 service 메서드 호출
        5-2. service() 메서드는 요청에 맞게 doGet() 또는 doPost() 등의 HTTP 메서드를 호출
    6) doGet() / doPost() 메서드는 인자에 맞게 생성된 동적 페이지를 Response 객체에 담아 WAS에 전달함
    7) WAS는 Response 객체를 HttpResponse 형태로 바꾸어 Web Server에 전달한다.
    8) 생성된 Thread를 종료하고, HttpServletRequest와 HttpServletResponse 객체를 제거한다( destroy() )


[어노테이션]
    * 사전적으로 '주석' 이라는 의미를 가짐.
    
    1) 정의: 자바 코드에 메타 데이터를 추가하는 문법
    * 메타 데이터 : 데이터를 위한 데이터, 작성된 코드가 어떻게 컴파일되고  실행되어야 하는지를 컴파일러/런타임 환경에 알려주는 설명서 역할을 함.

    2) 도입 목적
        메타데이터 제공: 컴파일러나 프레임워크에 코드의 의도와 동작 방식을 전달합니다.

        코드 간소화: 설정 파일(XML 등)에 작성해야 할 복잡한 설정을 코드 내에 선언적으로 작성하여 코드를 대폭 줄여줍니다.

        가독성 향상: 개발자가 코드의 역할(예: 이 클래스는 Controller구나)을 직관적으로 파악할 수 있게 해줍니다.

        컴파일 타임 에러 검출: 오타나 잘못된 재정의 등을 컴파일 단계에서 미리 잡아줍니다.
    
    3) 종류
    3-1. 표준 어노테이션 - 자바 자체에서 기본적으로 지원하는 어노테이션
        @Override : 부모 클래스나 인터페이스의 메소드를 재정의함을 컴파일러에게 명시합니다. (메소드 이름에 오타 발생 시 에러 발생)
        @Deprecated: 앞으로 사용을 권장하지 않는(곧 폐기될) 클래스나 메소드임을 알립니다.
        @SuppressWarnings: 특정 컴파일 경고를 무시하도록 설정합니다.


    3.2. 메타 어노테이션 (Meta Annotation)
        '어노테이션을 위한 어노테이션'입니다. 우리가 새로운 커스텀 어노테이션을 만들 때, 해당 어노테이션의 동작 대상을 지정하거나 유지 기간을 설정하는 용도로 사용됩니다. 

    @SpringBootApplication : Spring 실행할 때 spring에 필요한 기본 세팅 지원
                            (1. 내장톰캣지원, 2.서블릿자동등록)

    @RestController : Spring에선 서블릿을 상속이 아니라 @Controller 어노테이션으로 지원 + RestController (HTTP content type 자동으로 application/json으로 세팅)

    @GetMapping( "/board/findAll" ) : 만약, HTTP 요청이 GET이면 해당 메소드로 연결한다. + URL 만들기(중복없이) -> findAll()
    @PostMapping( "/board/save" ) : 만약, HTTP 요청이 POST이면 해당 메소드로 연결한다. + URL 만들기(중복없이) -> save()
    @PutMapping( "/board/update" ) : 만약, HTTP 요청이 PUT이면 해당 메소드로 연결한다. + URL 만들기(중복없이) -> update()
    @DeleteMapping( "/board/delete" ) : 만약, HTTP 요청이 DELETE이면 해당 메소드로 연결한다. + URL 만들기(중복없이) -> delete()

    4) 사용자 정의 어노테이션 만들기
        어노테이션 정의 시 필요한 것 -> 유지 기간(@Retention)과 적용 위치(@Target)
        4-1. @Retention : 어노테이션이 언제까지 유지될 것인가?
            RetentionPolicy.SOURCE: 컴파일 전(소스 코드 파일)까지만 유지됩니다. 컴파일 후 .class 파일에서는 사라집니다. (예: 롬복 @Getter)
            RetentionPolicy.CLASS: 컴파일 후 .class 파일에는 포함되지만, JVM이 실행될 때(Runtime)는 메모리에 올라가지 않습니다. (기본값)
            RetentionPolicy.RUNTIME: 프로그램 실행 중(Runtime)에도 유지됩니다. 리플렉션을 통해 런타임에 어노테이션 정보를 읽어 동작을 제어할 수 있습니다. (예: 스프링 어노테이션 대부분)

        4-2. @Target : 어노테이션을 어디에 적용시킬 것인가?
            ElementType.TYPE: 클래스, 인터페이스, 열거형(Enum)에 사용
            ElementType.METHOD: 메소드에 사용
            ElementType.FIELD: 멤버 변수(필드)에 사용
            ElementType.PARAMETER: 메소드의 파라미터에 사용
            ElementType.CONSTRUCTOR: 생성자에 사용


    5) 프레임워크(Spring): 개발자가 단순한 어노테이션을 명시하기만 하면, 스프링 내부적으로 복잡한 처리 과정을 대신 수행합니다.

        개발자의 입장: 컨트롤러 클래스 위에 @RestController라는 어노테이션 하나만 붙입니다.
        프레임워크의 입장: 스프링 컨테이너가 실행될 때, @RestController가 붙은 클래스들을 모두 찾아내어 내부적으로 HTTP 요청을 매핑하고, JSON 변환 객체를 생성하는 등(동적 로딩 및 빈 등록)의 복잡한 구현
        체 로직을 자동으로 실행합니다.


    6) 어노테이션을 가능케 하는 기술: 리플렉션(Reflection)
        스프링과 같은 프레임워크는 런타임에 개발자가 작성한 어노테이션을 동적 로딩과 리플렉션을 통해 알아채고 실행한다.

        6-1. 리플렉션이란?
            구체적인 클래스 타입을 알지 못하더라도 프로그램이 실행중인 런타임 환경에서 클래스의 구조(이름, 메소드, 필드, 적용된 어노테이션 정보 등)를 동적으로 읽어오고 객체를 조작할 수 있는 자바의 API
        
        6-2. 동적 로딩과 실행 예시
            프로그램 실행 중간에 필요한 시점에 클래스를 메모리에 로드하고 객체를 생성하는 방식입니다.

            JDBC 연동 예시: Class.forName("com.mysql.cj.jdbc.Driver"); :  컴파일 타임이 아닌 실행(Runtime) 중에 MySQL 드라이버 클래스를 찾아 로딩하고 객체를 생성함

            프레임워크의 어노테이션 스캔: 스프링은 애플리케이션 시작 시 리플렉션을 사용하여 모든 클래스를 스캔합니다. 그리고 @Retention(RetentionPolicy.RUNTIME)으로 설정된 어노테이션을 찾아내어, 미리 정의된 의존성 주입
            (DI)이나 AOP 기능 등을 런타임에 동적으로 부여합니다.

            구분    시스템/앱 클래스로더 (기본)     커스텀 클래스로더
            ClassLoader 수명    JVM이 종료될 때까지 상주    필요할 때 생성 및 폐기 가능
            클래스 언로드(GC) 여부      불가능 (클래스로더가 계속 살아있음)     가능 (클래스로더 참조가 끊기면 함께 GC됨)


[ axios ]

    1. 설치 : HTML 파일에 <script src="https://cdn.jsdelivr.net/npm/axios/dist/axios.min.js"></script> 코드 추가
    2. 사용법 : axios.HTTP메소드명("URL");
                주로 통신 이후에 결과를 제어 함으로써 동기화
                -> 
                async function 함수명() {
                    const response = await axios.HTTP메소드명("URL");
                    const data = response.data; 
                }

[Lombok]
    정의 : 자바의 고질적인 보일러플레이트 코드(Getter, Setter, 생성자, toString 등)를 어노테이션 기반으로 컴파일 시점에 자동 생성해 주는 생산성 향상 라이브러리.

    주요 적용 대상
        DTO : 계층(Controller - Service 등) 간 데이터 전송 객체

[스프링 빈]
    스프링빈은 스프링 컨테이너가 생성, 생명주기 관리, 의존성 주입을 대신 수행해주는 자바 객체이다.
